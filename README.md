# FMVS Vision Agent – 자율 영상 품질 관제 에이전트

FMVS 라이브 화면에 ROI를 여러 개 지정하고, **ROI마다 검출 유형·조건·담당자를 따로 설정**해 이상이 지속되면
팝업 + **Teams 채팅**으로 담당자에게 알리는 Windows 프로그램입니다.

## 기능

| 항목 | 내용 |
|---|---|
| ROI 지정 | 라이브 화면 위에서 드래그로 여러 개 지정 (멀티 모니터 지원) |
| 검출 유형 (ROI별) | 흑화면 · 백화면 · 단색(No Signal) · 화면 정지 · 특정 색상 · 기준 화면과 다름 · 형상 검사(탭 접힘·찍힘·휨) · **OK/NG 이미지 매칭(분류)** |
| 오탐 방지 | 이상 **지속 시간** 조건, ROI 위치의 **프로그램(프로세스) 확인** – 다른 창이 ROI 영역을 실제로 덮을 때만 건너뜀 |
| 알림 | 팝업(오른쪽 위 ✕로 닫기, 복구되면 초록색으로 변경), 경고음, Teams 카드, 재알림, 복구 알림 |
| 기록 | `logs/` 로그, `snapshots/` 경보 시점 ROI 이미지 |
| 조건 튜닝 | ROI 설정 창의 **[현재 화면으로 측정]** 으로 현재 값과 판정을 바로 확인 |

## 사용 순서

1. FMVS 라이브 화면을 띄운 상태에서 **[＋ 화면에서 ROI 추가]** → 감시할 영역을 드래그(여러 개 가능) → Enter
2. ROI마다 설정 창이 뜨면 검출 유형/조건, 지속 시간, 담당자를 입력하고 **[현재 화면으로 측정]** 으로 확인 후 저장
   - 대상 프로그램(예: `NVR_VIEWER.exe`)은 ROI를 그릴 때 자동으로 채워집니다.
   - "기준 화면과 다름" 유형은 정상 화면일 때 **[기준 이미지 저장]** 을 눌러야 동작합니다.
3. **[⚙ 설정]** 에서 Teams 알림 사용 + 공통 Webhook URL 입력 → **[Teams 테스트]** 로 수신 확인
4. **[▶ 검출 시작]** (메인 창은 ROI를 가리지 않도록 자동 최소화)

## 비전 에이전트 (관찰 → 판단 → 실행 → 학습)

PC 내부에서만 동작하는 자율 에이전트가 검출 결과를 지켜보며 스스로 원인을 추론하고 행동합니다. 화면·이미지를 외부로 보내지 않습니다.

| 단계 | 에이전트가 하는 일 |
|---|---|
| 👁 관찰 | 모든 ROI의 판정·경보·복구·가려짐·오류를 실시간 수집, ROI별 판정 수·NG 수·시간대별 NG 집계 |
| 🧠 판단 | 15초 안에 ROI 절반 이상 동시 이상 → **개별 불량이 아니라 FMVS 화면 전체 문제**(레이아웃 변경·영상 끊김)로 추론 / 같은 ROI 10분 내 3회 불량 → **공정·설비 추세**로 판단 / 60초 이상 가려짐 → FMVS 창 가려짐·최소화로 추정 |
| ⚡ 실행 | 원인 추정을 담은 통합 Teams 알림, 설비 점검 에스컬레이션, 검출 엔진 오류 시 **자동 재시작**(시간당 3회 한도, 초과 시 반복 장애 알림), 교대 시각에 **근무 리포트 자동 작성** |
| 📚 학습 | 경보 팝업의 [OK로 등록]/[NG로 등록] 피드백 → 샘플 반영 후 OK 허용 거리 **자동 재보정** 값 기록 |

- 근무 리포트: `reports/report_YYYYMMDD_HHMM.html` (KPI, ROI별 현황, 에이전트 판단 기록, 이벤트 타임라인). 상단 [📄 리포트 생성]으로 즉시 작성 가능
- [⚙ 설정] → 비전 에이전트: 자동 재시작 / 판단 결과 Teams 전송 / 교대 시각 / 리포트 Teams 전송

## 의견 에이전트 (💡 의견 탭)

대시보드 오른쪽 위 [💡 의견] 탭. 5분마다(또는 [⟳ 다시 분석]) 검출 기록·샘플·설정을 분석해 **운영 개선 의견**을
우선순위(긴급 → 주의 → 참고)로 보여 줍니다. 각 의견에 [샘플 열기]/[ROI 편집]/[설정 열기] 버튼이 있고, [숨기기]로 감출 수 있습니다.
새 긴급·주의 의견은 활동 로그에도 한 줄로 알립니다. **LLM 없이 PC 안에서 동작**합니다.

| 분석 | 의견 예 |
|---|---|
| 샘플 | OK 샘플 없음(판정 불가) · OK 3장 미만(오탐 위험) · 자체 검증 실패 · '무시' 샘플 없음 |
| 가림 | 30% 이상 시간 동안 가려져 판정 못 함 (가린 프로그램 표시) |
| 정지 판정 | 정지를 한 번도 감지 못 함 → 정지 기준 값 조정 제안 |
| NG | NG 비율 20% 이상 · 최근 1시간 NG 급증(이전 평균의 3배) |
| 설정 | 대상 프로그램 미지정 · 담당자 미지정 · NG가 나는데 Teams 꺼짐 · 검사 오류 반복 |

### LLM 연결 (선택 – 나중에 설치 후 사용)

[⚙ 설정 → LLM 연결]에서 **이 PC 또는 사내 서버**의 LLM을 켜면, 같은 분석 자료로 **자연어 종합 의견**([✦ LLM 종합 의견])과
**질문 답변**(의견 탭 아래 입력칸)을 받습니다. 연결 전에는 예시 답변이 회색 카드로 표시됩니다.

1. LLM 서버 설치 (예: [Ollama](https://ollama.com) 설치 후 `ollama pull qwen2.5:7b`) – OpenAI 호환 API를 제공하면 무엇이든 가능 (LM Studio, vLLM, llama.cpp server)
2. 설정 → LLM 사용 체크 · 서버 주소 `http://127.0.0.1:11434/v1` · 모델 `qwen2.5:7b` → [연결 테스트]
3. 의견 탭에서 [✦ LLM 종합 의견] 또는 질문 입력 → [묻기]

- **보안**: localhost·사내망(10.x / 172.16~31.x / 192.168.x) 주소만 허용, 외부 인터넷 주소는 저장 자체가 안 됩니다. 시스템 프록시를 거치지 않고 직접 연결합니다.
- **보내는 내용**: ROI 이름·검출 유형·판정 수·상태 횟수·샘플 수·의견 목록(텍스트)뿐. 화면·이미지·스냅샷은 보내지 않습니다.
- 추가 패키지 없이 동작합니다 (표준 라이브러리 HTTP).

## 운영 설정 (⚙ 설정 → 팝업 · 미니 모니터 · 보관)

| 항목 | 기본값 | 설명 |
|---|---|---|
| 연속 이상 발생 시 팝업 | 1회 | 같은 ROI에서 연속 n회 NG 판정되면 팝업. OK 판정이 나오면 0으로 초기화 (Teams 알림은 판정마다 전송) |
| 미니 모니터 | 켜짐 · 자동 위치 | 검출 시작 시 화면 하단(오른쪽/왼쪽, 자동은 ROI와 덜 겹치는 쪽)에 ROI별 NG 트렌드 표시. 캡처에서 제외되어 판정에 영향 없음. [대시보드 열기] / ■ 정지 |
| 보관 기간 | 15일 (최대 15일) | 로그·스냅샷·리포트를 시작 시와 1시간마다 정리. 로그 파일은 자정마다 새로 생성 (`logs/fmvs_agent.log`) |

- 리포트에는 **NG 탐지 이미지(최근 40장)와 리포트 작성 시점의 ROI 화면**이 파일 안에 포함되어, 스냅샷이 보관 기간 후 지워져도 리포트에서 볼 수 있습니다.
- ROI [편집]·[위치 재지정] 시 **샘플/기준 이미지는 삭제하지 않습니다.** 위치 재지정에서 크기가 다르면 "기존 크기 유지(위치만 이동)"를 고를 수 있고, 크기를 바꾸면 샘플을 새 크기에 맞춰 유지합니다.

## 검출 중 화면 표시

검출을 시작하면 모니터 위에 다음이 표시됩니다 ([설정]에서 각각 끄기 가능).

| 표시 | 내용 |
|---|---|
| ROI 테두리 | 각 ROI 바깥쪽에 상태 색 테두리 + `이름 · 상태` 이름표. 정상=초록, 경보=빨강(깜빡임), 움직임=남색, 건너뜀=회색 |
| 동작 중 배지 | 주 모니터 모서리(ROI와 안 겹치는 곳)에 `● FMVS 검출 중 · ROI n개 · 시각` – 점이 깜빡이고 시각이 계속 바뀌면 정상 동작 |
| 경보 배지 | 경보가 있으면 배지가 빨간색 `경보 n건` |
| 응답 없음 | 검출 스레드가 10초 이상 결과를 못 보내면 `⚠ FMVS 검출기 응답 없음` |

- 화면 표시는 **클릭이 통과**하므로 FMVS 프로그램 조작에 방해되지 않고, 대상 프로그램 확인에서도 무시됩니다.
- **화면 캡처에서 제외**(Windows 10 2004 이상)되어 판정에 영향이 없습니다. 미지원 Windows에서는 로그에 경고가 뜨며,
  테두리는 ROI 바깥에만 그리지만 ROI끼리 붙어 있으면 옆 ROI에 걸칠 수 있으니 화면 표시를 끄세요.

## OK/NG 이미지 매칭 (흐르는 라인 실시간 모니터링 권장)

ROI마다 **OK·NG·무시** 샘플 이미지를 등록하면, 현재 화면과 가장 비슷한 샘플 종류로 판정합니다.
한 화면에 카메라가 많아 ROI가 작고 "최소 불량 크기"를 정하기 어려운 경우에 적합합니다.

| 현재 화면이 가장 비슷한 것 | 판정 |
|---|---|
| NG 샘플 | 🚨 불량 |
| OK 샘플이지만 **OK 허용 거리**보다 멂 | 🚨 불량 (NG 샘플에 없는 새로운 불량) |
| OK 샘플 (허용 거리 이내) | ✅ 정상 |
| 무시 샘플 (제품 없음·이동 중·가려짐) | ⏸ 판정 보류 |

- **거리**: 밝기를 정규화(조명 변화 무시)하고, 위치 허용 범위 안에서 가장 잘 겹치는 위치의 차이(0 = 동일).
- **OK 허용 거리 자동 계산**(값 0): OK끼리의 최대 편차와 NG→OK 최소 거리의 중간값. [샘플/기준 이미지] 창 하단에 분리 상태가 표시됩니다
  (`분리 양호` 또는 `⚠ OK/NG가 겹침`).

설정 순서
1. ROI 설정 → 검출 유형 **OK/NG 이미지 매칭** (이상 지속 시간이 자동으로 0초, 복구 알림 꺼짐으로 바뀝니다)
2. 목록에서 ROI 선택 → **[샘플/기준 이미지]**
   - OK: [현재 화면 추가]를 제품 위치를 바꿔가며 3장 이상
   - NG: 과거 불량 사진을 [파일에서 가져오기] (FMVS 화면에서 ROI 영역만 잘라낸 이미지 권장, ROI 크기에 맞춰 저장됨)
   - 무시: 제품이 없을 때 / 반쯤 들어온 화면
3. 창 하단의 `분리 양호` 확인 → [검출 시작]
4. 운영 중 경보 팝업에서 바로 학습: 오탐이면 **[OK로 등록(오탐)]**, 실제 불량이면 **[NG로 등록]** → 다음 검사부터 반영

### 샘플 이미지 (OK · NG · 무시) – 모든 이미지 비교 유형 공통

OK/NG 매칭 · 형상 검사 · 기준 화면과 다름 유형 모두 [🖼 샘플/기준 이미지]에서 세 종류를 등록합니다.

| 종류 | 등록할 화면 | 판정에 쓰는 방법 |
|---|---|---|
| OK | 정상품 (위치·모양 편차가 있으면 여러 장) | 가장 비슷한 OK와 비교 |
| NG | 불량품 (접힘·찍힘·휨 등 유형별, 과거 사진 파일 가능) | NG와 더 비슷하면 불량 |
| 무시 | **셀이 없을 때**·이동 중·가려진 화면 | 이것과 가장 비슷하면 판정하지 않음 |

- **잘못 등록한 이미지**는 썸네일을 다른 칸(OK/NG/무시)으로 끌어 놓거나, 우클릭 → 이동으로 옮깁니다 (이미지는 그대로, 분류만 변경).
- 등록하면 창 하단에서 **자체 검증**(각 샘플을 빼고 나머지로 판정해 맞히는지)을 자동 실행합니다: `✔ 자체 검증 통과: OK 5/5 · NG 3/3 · 무시 2/2`
- 형상 검사는 셀 면적이 기준의 30% 미만(설정 가능, 최소 5%)이면 **제품 없음으로 판정 보류**합니다.
- 경보 팝업에서 바로 **[NG로 등록] [OK로 등록(오탐)] [무시로 등록(셀 없음)]** 가능 → 다음 검사부터 반영

### 탐지 팝업

- **탐지 시각(이 PC의 로컬 시간)** 을 크게 표시하고, 같은 ROI의 탐지 횟수·이전 탐지 시각을 함께 표시합니다.
- 팝업은 **감시 중인 ROI 좌표와 다른 팝업을 피해서** 주 모니터의 빈 곳에 뜹니다 (ROI를 가리면 판정이 막히므로). 빈 곳이 없으면 가장 적게 겹치는 곳. 헤더를 끌어 옮기면 그 위치를 유지합니다.

### 정지 시에만 판정 (움직이는 대상)

ROI 설정의 **[정지 시에만 판정]** 을 켜면, 대상이 움직이는 동안은 판정하지 않고 **멈춘 순간 1회만** 판정합니다.
(OK/NG 매칭·형상 검사 유형을 고르면 자동으로 켜집니다. 모든 검출 유형에서 사용 가능, 화면 정지 유형 제외)

| 상황 | 동작 | 목록 상태 |
|---|---|---|
| 직전 캡처 대비 변화량 > 정지 기준 | 판정 안 함 | 움직임(대기) |
| 변화 없음이 연속 n회(정지 확인 횟수) | **그 순간 1회 판정** | 정상 / 🚨 경보 |
| 계속 정지 중 | 다시 판정하지 않고 결과 유지 | (유지) |
| 다시 움직였다가 정지 | 새 제품으로 보고 다시 판정 | |

- NG 정지마다 경보, 직전 경보 후 OK 정지면 복구 표시 (이상 지속 시간은 사용 안 함)
- **정지 기준 변화량**: [현재 화면으로 측정]이 0.5초 간 변화량을 보여줍니다. 정지 상태 값(영상 노이즈)보다 조금 크게 설정 (기본 3)
- 검사 주기 × 정지 확인 횟수보다 오래 멈춰야 판정됩니다 (예: 0.3초 × 2회 = 0.6초 이상 정지)

> 흐르는 라인은 화면 캡처 주기(설정의 검사 주기) 사이에 지나간 제품은 볼 수 없습니다.
> 제품이 ROI에 머무는 시간보다 검사 주기를 짧게(예: 0.3~0.5초) 설정하세요. ROI가 4개 이상이면 전체를 한 번에 캡처해 속도를 높입니다.

## 형상 검사 (탭 접힘·찍힘·휨)

정상 제품 화면을 기준 이미지로 저장해 두고, 들어오는 제품의 **윤곽(실루엣)** 을 기준과 겹쳐 모양이 달라진 면적을 잽니다.

| 단계 | 처리 |
|---|---|
| 1. 대상 분리 | 이미지마다 자동 임계값(Otsu)으로 탭과 배경 분리 → 조명 밝기 변화에 강함 |
| 2. 위치 맞춤 | 기준과 가장 잘 겹치는 위치로 자동 이동 보정 (허용 범위 설정 가능) |
| 3. 차이 측정 | 겹치지 않는 면적 ÷ 기준 탭 면적 = **형상 차이 %**. 정렬 오차로 생기는 1~2px 경계선은 제거 |
| 4. 판정 | 형상 차이 ≥ 기준 % → 불량. 스냅샷에 불량 위치를 **빨간색**으로 표시 |

설정 방법
1. 탭이 잘 보이도록 **ROI를 탭 주변으로 좁게** 지정 (배경이 너무 넓으면 작은 불량의 비율이 낮아짐)
2. 정상품이 화면에 있을 때 **[기준 이미지 저장]**. 정상품도 모양 편차가 있으면 여러 번 눌러 **추가** (가장 비슷한 기준과 비교)
3. ROI 설정 창의 **[현재 화면으로 측정]** 으로 정상품/불량품의 형상 차이 %를 확인하고 그 사이 값으로 기준 설정
4. 제품이 흘러가는 라인이면 **이상 지속 시간 0~1초**, 제품이 없을 때 오탐이 나면 **제품 감지 최소 면적**(예: 50%) 설정
5. 구김·긁힘처럼 윤곽은 그대로인 손상은 **표면 차이 기준**(예: 0.5부터 조정)을 켜서 감지

합성 이미지 기준 검증 결과 (기본값 5%)

| 경우 | 형상 차이 | 판정 |
|---|---|---|
| 정상 (위치 이동 12px, 노이즈, 회전 2°, 조명 변화) | 0.0% | 정상 |
| 접힘 15% / 35% | 14.5% / 34.5% | 불량 |
| 휨 10px / 25px | 16.2% / 41.2% | 불량 |
| 찍힘 25×25px (탭 면적의 7%) | 6.5% | 불량 |
| 찍힘 15×15px (탭 면적의 2.5%) | 2.1% | **미검출** → 기준을 2%로 낮추면 검출 |

한계
- 회전은 약 2° 이내만 보정합니다. 그 이상 기울어져 들어오면 정상품도 차이가 커집니다.
- 탭과 배경의 밝기 차이가 거의 없으면 윤곽을 분리할 수 없습니다 (기준 저장 시 안내 메시지 표시).
- 실제 판정 품질은 FMVS 영상 해상도/압축 상태에 따라 달라지므로, 정상품·불량품 실물로 측정해서 기준을 맞추세요.

## Teams 알림 설정 (Power Automate Workflows)

Teams 앱 화면을 자동 조작하는 방식은 Teams 업데이트·화면 잠금·팝업·포커스 변경 시 **조용히 실패**하므로 쓰지 않습니다.
대신 Microsoft 공식 **Workflows 웹훅**으로 HTTP 요청 한 번에 메시지를 보냅니다. 감시 PC에 Teams가 로그인되어 있지 않아도 됩니다.
(메뉴 이름은 Teams/Power Automate 버전에 따라 조금 다를 수 있습니다.)

### 방법 A – 채팅방/채널 하나로 받기 (가장 간단)
1. Teams에서 알림을 받을 채팅(담당자들이 들어간 그룹 채팅 등) 또는 채널을 엽니다.
2. `…` → **워크플로(Workflows)** → 템플릿 **"웹후크 요청이 수신되면 채팅에 게시" / "Send webhook alerts to a chat"** 선택
3. 생성 완료 화면의 **URL을 복사** → 프로그램 [설정] → 공통 Webhook URL에 붙여넣기
4. ROI마다 다른 방으로 보내려면 방마다 흐름을 만들어 ROI 설정의 **개별 Webhook URL** 에 넣습니다.

### 방법 B – 담당자 개인 채팅으로 자동 분배 (흐름 1개)
프로그램이 보내는 JSON에 `assignee_email` 이 들어 있으므로, 흐름 하나로 담당자별 1:1 채팅을 보낼 수 있습니다.
1. Power Automate → **인스턴트 클라우드 흐름** → 트리거 **"Teams 웹후크 요청을 받은 경우 (When a Teams webhook request is received)"**,
   누가 트리거할 수 있는지: **모든 사용자(Anyone)**
2. 작업 **"채팅 또는 채널에 카드 게시 (Post card in a chat or channel)"**
   - 게시자: 흐름 봇 / 게시 위치: 흐름 봇과 채팅
   - 받는 사람: 식 `triggerBody()?['assignee_email']`
   - 적응형 카드: 식 `string(triggerBody()?['attachments'][0]['content'])`
3. 저장 후 트리거의 HTTP URL을 프로그램의 공통 Webhook URL에 입력
4. ROI 설정에 **담당자 이메일(회사 Teams 계정)** 을 반드시 입력

전송되는 JSON (요약):
```json
{
  "event": "alert | repeat | recover | test",
  "title": "🚨 FMVS 화면 이상 감지",
  "message": "[1번 카메라] 화면에서 '흑화면 (검은 화면)' 이상이 감지되었습니다. 확인 부탁드립니다.",
  "roi_name": "1번 카메라", "detector": "흑화면 (검은 화면)", "detail": "어두운 픽셀 100.0% (기준 ≥95%)",
  "assignee": "홍길동", "assignee_email": "hong@example.com",
  "pc": "NVR-PC", "time": "2026-10-06 12:00:00", "elapsed_sec": 75,
  "type": "message",
  "attachments": [ { "contentType": "application/vnd.microsoft.card.adaptive", "content": { "...": "적응형 카드" } } ]
}
```

> ⚠ Webhook URL에는 인증 서명이 포함되어 있습니다. 외부에 공유하지 말고, `settings.json` 은 저장소에 올리지 마세요 (`.gitignore` 처리됨).

## 빌드 (EXE)

Windows에서 `build.bat` 실행 → `dist\FMVS_Vision_Agent.exe`
(직접: `pip install -r requirements.txt pyinstaller` 후 `pyinstaller --noconfirm --clean FMVS_Vision_Agent.spec`)

실행 파일 옆에 `settings.json`, `logs/`, `refs/`, `snapshots/` 가 생성됩니다.
구버전(흑변 전용) `settings.json` 을 EXE 옆에 두면 첫 실행 시 자동 변환되고 원본은 `settings.v1.bak.json` 으로 백업됩니다.

## 주의 사항

- **화면 잠금/화면 보호기**: 잠긴 화면은 캡처가 검게 나옵니다. 대상 프로그램 확인을 켜두면 "확인 불가"로 건너뛰지만, 감시 PC는 잠금/절전을 해제해 두세요.
- **화면 정지 검출**: 움직임이 없는 장면(야간 빈 복도 등)은 정상이어도 정지로 보일 수 있습니다. 지속 시간을 길게(60초 이상) 두고, ROI에서 시계 표시는 빼세요.
- **팝업/대시보드 창이 ROI를 실제로 덮으면** 해당 ROI는 "건너뜀 – 다른 창이 ROI를 가림: FMVS 창 35%"처럼 가린 프로그램과 면적을 표시합니다. 대시보드가 떠 있어도 ROI와 겹치지 않으면 정상 판정합니다. 창 가장자리 2px 이내 겹침, 보이지 않는 창 테두리·그림자, 다른 가상 데스크톱의 창, 화면 캡처에서 제외된 창(화면 표시·미니 모니터)은 가림으로 보지 않습니다.
- **FMVS 화면 레이아웃(분할 수, 창 위치)이 바뀌면** ROI 좌표가 어긋나므로 [위치 다시 지정]을 해야 합니다.
- **회사 프록시/SSL 검사** 환경에서는 Teams 전송이 실패할 수 있습니다. 실패 내용은 로그 창과 `logs/` 에 남습니다.
